# Architecture Decision Record (ADR-002)
## Implementation of Reciprocal Rank Fusion (RRF) for Hybrid Search

### Status
**Approved**

### Context & Problem Statement
Ocean's search engine must process standard keyword matches (such as SKU numbers, model numbers like "WH-1000XM4", and brand names) as well as natural language queries representing abstract customer intent (e.g., "minimalist walnut workspace desk under 500 dollars"). 

Independently, lexical search is fast and precise for exact words but fails to understand semantic relationships. Vector search is excellent at conceptual matching but struggles with exact model codes or specific brands. We need a robust strategy to combine these two disparate query pathways into a single, high-relevance results list.

### Decision Drivers
1. **Normalized Scoring:** Lexical search returns text-ranking metrics (e.g., TF-IDF or BM25 scores, which can exceed $1.0$ arbitrarily). Vector search returns similarity scores (e.g., Cosine metrics, which range from $-1.0$ to $1.0$). These metrics cannot be added or normalized reliably.
2. **Execution Latency:** Merging algorithms must be lightweight and operate in under 10ms to satisfy our overall target latency of <350ms.
3. **Relevance Consistency:** Brand names and exact match results must rank high, but abstract fits should seamlessly fill subsequent ranks.

### Considered Options
* **Option A: Weighted Score Linear Combination** (Scale, normalize, and sum raw scores: $Score = w_1 \cdot Lexical + w_2 \cdot Vector$)
* **Option B: Two-Pass Re-ranking Model** (Query lexical first, feed top 100 hits to an AI model for re-scoring)
* **Option C: Reciprocal Rank Fusion (RRF)** (Combine ordinal positions in result lists mathematically)

---

### Pros and Cons of Options

#### Option A: Weighted Score Linear Combination
* **Pros:** Simple to implement mathematically inside database query layers.
* **Cons:** High maintenance. Changes in the keyword catalog or vector dimension require recalibrating arbitrary weights. Scores fluctuate unpredictably, leading to bad relative ranking.

#### Option B: Two-Pass Re-ranking Model
* **Pros:** Extremely high semantic precision.
* **Cons:** High computational overhead. Adding secondary AI model evaluation steps introduces an extra 200ms–800ms to request lifecycles, violating our strict INP and latency budgets.

#### Option C: Reciprocal Rank Fusion (RRF)
* **Pros:** Scale-invariant and parameter-free. It does not rely on raw scoring values, only on the relative rank positions within each list:
  $$RRF(d) = \sum_{m \in M} \frac{1}{k + r_m(d)}$$
  Where $k$ acts as a stabilizer (typically $60$).
* **Pros:** High performance, constant time merge, resilient to extreme score variations, and easily computed in a single processing step.
* **Cons:** Relies on retrieving a reasonable set of initial documents (e.g., Top 50) from both pathways to perform accurate rank fusion.

---

### Decision Outcome
We selected **Option C: Reciprocal Rank Fusion (RRF)**. 

RRF delivers excellent relevance without the maintenance burden or vulnerability to scoring scale mismatches that linear models suffer from. By using ordinal positions, exact keyword matches and conceptual associations are perfectly combined.

#### Consequences
* **Precision:** Exact SKU queries land at position 1 (due to high lexical rank), while conceptual matches fill the remaining slots.
* **Performance:** The fusion is executed in memory in under 2ms inside the Express Search API layer, keeping search responses extremely responsive.
